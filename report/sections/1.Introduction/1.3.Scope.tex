\section{Scope}

This project covers the full path from synthetic event generation to dashboarding: Eventsim event generation, Kafka ingestion, Spark Structured Streaming processing into Hudi bronze tables, dbt transformation into a star schema and wide table, Superset dashboarding, and Prometheus/Grafana monitoring of the pipeline's own health (Chapter~\ref{ch:proposed-solution}). Within this path, the scope also includes the distributed-systems concerns the course covers -- partitioning, replication, checkpointed exactly-once processing, and consumer-lag monitoring (Section~\ref{sec:core-theory}) -- rather than just wiring the tools together. All of these components are deployed and demonstrated together via Docker Compose on a single machine.

The following are explicitly out of scope:

\begin{itemize}
    \item \textbf{Production security hardening.} Authentication, authorization, network isolation, secrets management, and TLS between services are not addressed; the stack is configured for local development and demonstration, not for exposure to untrusted networks.
    \item \textbf{Multi-region or high-availability production deployment.} The pipeline targets a single-machine, single-region Docker Compose deployment (Section~\ref{sec:proposed-cluster-setup}); cross-region replication, multi-datacenter failover, and elastic autoscaling of the Kafka or Spark clusters are not implemented.
    \item \textbf{Real user data.} All events are generated by Eventsim against the Million Song Dataset's 10,000-song subset (Chapter~\ref{ch:problem-statement}) and are entirely synthetic; the pipeline has not been run against real production traffic or real user data.
\end{itemize}
