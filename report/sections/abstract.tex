\chapter*{Abstract}

This thesis presents \emph{Streamify}, an end-to-end streaming lakehouse pipeline built to demonstrate real-time data engineering under a small, fixed compute budget. Synthetic music-streaming events, generated by Eventsim against the Million Song Dataset, are ingested through a 2-node Apache Kafka (KRaft) cluster, consumed by an Apache Spark Structured Streaming job, and landed as MERGE\_ON\_READ Apache Hudi bronze tables on MinIO/S3-compatible object storage.

\noindent dbt then transforms the bronze layer, through the Spark Thrift Server, into a COPY\_ON\_WRITE star schema (a \texttt{fact\_streams} table and five dimension tables) and a denormalized \texttt{wide\_streams} table, which Apache Superset visualizes through interactive dashboards. A Prometheus/Grafana/cAdvisor stack monitors Kafka consumer lag and Spark resource usage throughout, and the entire system is deployed reproducibly with a single Docker Compose command.

\noindent Every major technology choice in the pipeline -- Kafka over HTTP or RabbitMQ, Spark Structured Streaming over Flink, Hudi over plain Parquet or a managed warehouse, dbt over hand-written SQL scripts, and Spark Standalone over YARN or Kubernetes -- is justified against concrete alternatives and the resource constraints of a single-machine, 4-core deployment, rather than assumed as a given. This thesis documents that reasoning alongside the resulting architecture and its observed operational behavior.
